# MedLab OCR API

Асинхронный бэкенд на **FastAPI** для автоматического распознавания, парсинга и структурирования данных из медицинских бланков и результатов анализов. 

Система берет на себя всю грязную работу: принимает файлы разных форматов (от кривых фоток до таблиц Excel), вытаскивает из них сырой текст с помощью OCR и готовит структурированные данные для ИИ-интерпретации.

---

## Стек & Архитектура

* **Фреймворк:** `FastAPI` + `Pydantic v2` (строгая валидация входящих данных, пагинация и фильтрация списков).
* **База данных:** `PostgreSQL` + `SQLAlchemy 2.0 (Async)` + `asyncpg`. Сессии инжектируются через FastAPI Dependencies (`Depends`) и работают в асинхронном режиме.
* **Мультиформатный OCR-слой:**
  * **Изображения (PNG, JPEG, WEBP):** распознавание через `Tesseract OCR`.
  * **Документы PDF:** поочередный парсинг страниц с предварительной конвертацией в байты через `pdf2image`.
  * **Таблицы (CSV, Excel):** автоматическое считывание структуры данных через `Pandas`.

**Оптимизация потоков:** Все тяжелые синхронные операции парсинга (работа с `pytesseract`, `pandas`, `pdf2image`) изолированы и запускаются в отдельном пуле потоков через `run_in_threadpool`. Это позволяет серверу оставаться отзывчивым и не блокировать основной асинхронный цикл (`event loop`) при обработке больших файлов.

## Технический кейс: Как универсальный декоратор чуть не сломал AnyIO

В процессе разработки я столкнулся с неочевидной и очень интересной проблемой, которая отлично иллюстрирует внутреннее устройство Python и FastAPI.

### С чего всё началось:
Мне нужно было замерить время работы парсеров для логирования. Я написал классический синхронный декоратор времени, используя `functools.wraps` со свободной сигнатурой `(*args, **kwargs)`. Обернул им функции парсинга.

### Что пошло не так:
При попытке отправить обернутую функцию в пул потоков через `run_in_threadpool`, приложение намертво падало с ошибкой:
`TypeError: the first argument must be callable`
При этом без декоратора всё работало идеально, а сам декоратор синтаксически был написан без ошибок.

### В чем была реальная причина:
Как оказалось, под капотом FastAPI использует библиотеку `AnyIO`. Перед тем как закинуть задачу в `ThreadPoolExecutor`, `AnyIO` жестко инспектирует её аргументы через встроенный модуль `inspect`. 

Несмотря на то, что `functools.wraps` честно копирует имя функции и её докстринги, он скрывает реальную сигнатуру параметров за общей маской `*args, **kwargs`. Механизм инспекции `AnyIO` просто запутался в порядке передачи позиционных и именованных аргументов и попытался выполнить вызов над некорректным внутренним объектом.

### Как я это решил:
1. **Чистые функции:** Я убрал декораторы со свободной сигнатурой с функций, которые передаются внутрь системных механизмов фреймворка. Парсеры остались «голыми».
2. **Явный замер:** Логирование и замер времени выполнения перенес напрямую внутрь асинхронного метода-фасада `extract_text` прямо перед отправкой задачи в пул потоков.
